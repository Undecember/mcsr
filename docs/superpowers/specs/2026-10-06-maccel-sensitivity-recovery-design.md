# MCSR Toolkit maccel sensitivity recovery design

## Context and goal

The existing eye zoom controller uses `maccel set param sens-mult` after a successful Minecraft resize. On this Ubuntu GNOME Wayland device, maccel 0.6.0 is installed and `get` reports `1.000000000`, but the same desktop login cannot set even that unchanged value: `/sys/module/maccel/parameters/SENS_MULT` is currently `root:maccel` mode `0664`, the login is not in that group, and the write returns permission denied. No eye zoom write has been performed.

Adding the login to the upstream `maccel` group is outside this design. The installed CLI writes executable reset scripts under `/var/opt/maccel/resets`, and the installed udev ownership helper grants that group write access to the scripts and executes them as root when the module is added. The toolkit must not make those scripts writable to its service user. This addendum supersedes the original spec's direct unprivileged `maccel set` path; keyd, window sizing, and profile semantics otherwise remain as specified.

The goal is temporary eye zoom sensitivity `0.02083` on a focused Minecraft window, exact restoration of the pre-zoom multiplier, and recovery after a service crash, without granting the desktop login access to executable reset scripts or changing maccel's persistent settings.

## Privilege boundary

A separately reviewed, self-contained root-owned executable is installed at `/usr/local/libexec/mcsr-toolkit-maccel`. It accepts exactly two argument-free commands: `eye` and `restore`. A user-specific sudoers rule permits only those exact invocations without a password. The service never runs as root and the browser cannot select a command, value, or path. No user is added to the `maccel` group; the toolkit neither invokes `maccel set` nor edits `/var/opt/maccel/resets` or the upstream udev rule. The helper has no general-purpose shell or file-writing interface.

The helper writes only the fixed kernel parameter path `/sys/module/maccel/parameters/SENS_MULT`. It reads `/sys/module/maccel/srcversion` to identify the installed driver's observed Q32 representation (`4AFA0F5B3EBD2F98EE54E56` on this device), then validates a canonical signed 64-bit raw integer; a missing or different fingerprint fails closed. It writes the fixed eye value using that representation, then checks the value read back. `restore` writes back the exact raw pre-zoom value and checks it, so a user's normal multiplier need not be `1`. The initial accepted implementation supports only this observed 64-bit, 32-fraction-bit representation; it must not guess a conversion on an unrecognized driver. `1` remains the documented reference normal multiplier, not an override of a readable prior value.

The helper keeps a root-owned, mode `0700` runtime directory under `/run` with an exclusive lock, a mode `0600` generation record, and a mode `0600` baseline record when eye zoom is active. It saves and syncs the exact pre-zoom raw value **before** writing eye sensitivity. Repeated `eye` calls preserve that first baseline. A failed write or readback leaves the record for recovery. `restore` is idempotent when no baseline exists; when one exists, it removes it only after verified restoration. Symlinks, unexpected ownership or mode, malformed records, and an unhealthy or absent maccel parameter fail closed. The records are runtime-only: a reboot returns control to the driver's existing module initialization, not to a toolkit-written reset script.

To prevent an orphaned `eye` process from applying sensitivity after service restart, every `restore` rotates the root-owned generation and returns its new opaque value to the service. `eye` receives that value on standard input before waiting for the helper lock, then checks it again under the lock immediately before writing. A queued helper from an earlier service generation is rejected even if it runs after startup recovery. A missing, malformed, or stale value is rejected. The value is a freshness token, not an authorization secret; command and target restrictions remain enforced by the fixed sudoers rule and helper. The service rotates its token on startup and after every restore. A failed restore must not issue a token that permits another eye write. This protocol also covers a service killed while an already spawned helper is waiting for the lock.

## Service behavior and failure recovery

The controller invokes the helper only after the extension confirms the eye window size and a fresh effective-focus check. A shifted eye shortcut resizes without writing sensitivity. A normal preset, observed Minecraft blur, observed Shell modal entry, extension disconnect or heartbeat loss, service shutdown, and the next service startup invoke `restore`. Startup recovery rotates the generation and completes before accepting new eye zoom actions. An asynchronous transition lock serializes preset handlers across focus-check awaits, while the existing thread lock coordinates synchronous focus and restore work. Each new preset, blur, disconnect, and shutdown invalidates older pending eye work; a stale handler cannot activate sensitivity after a later normal preset or cleanup, even if it resumes after an await. Pending handlers are drained or cancelled on disconnect and shutdown. After the helper returns, the service immediately rechecks effective focus and restores sensitivity if focus was lost during the operation. GNOME focus and modal signals arrive asynchronously, so a brief interval before the service observes a change remains possible; the toolkit does not promise zero sensitivity leakage during that interval.

The service reports eye zoom available only when maccel is readable, the reviewed helper is root-owned and executable through a nonwritable path, the exact sudo permissions are present, and no recovery is pending. A successful read alone is insufficient. Any helper failure, invalid readback, or failed restoration clears the active eye claim, leaves a visible recovery state, retries restoration where safe, and blocks another eye write until restoration succeeds. The helper's root-owned record is the authority after a service crash; an unprivileged process must not delete or rewrite it to bypass recovery.

If restoring sensitivity cannot be confirmed, the toolkit must not report normal sensitivity. The operator can use the exact helper `restore` command and independently read `maccel get param sens-mult`; removal or broader repair of the upstream installation is outside this toolkit's scope. Deploying the helper and sudoers rule is a separate security-sensitive system change requiring explicit approval after source review.

## Verification and acceptance

Automated tests cover command and path rejection, ownership and symlink checks, raw-value conversion, baseline-before-write order, repeated eye calls, concurrent eye/restore serialization, partial write and readback failures, retry and startup recovery, exact sudo scope, status honesty, and absence of `maccel set` or reset-script writes. Tests exercise both a non-`1` baseline and unsupported driver representation. A process-level test kills the service while an already spawned `eye` helper waits for the lock, then confirms startup `restore` invalidates that stale call. Focus-loss tests cover changes during resize and helper execution. Overlapping eye/normal preset signals and a pending focus call during disconnect or shutdown must leave sensitivity restored. Independent security review precedes deployment.

After separate deployment approval, a supervised GNOME Wayland test starts an isolated observe-only service with no keyd mappings. It records the original raw and CLI multiplier, then measures F7 eye zoom at 400×300 and about `0.02083`; Shift+F7 leaves the current multiplier unchanged; F6 restores the original value at 800×600. Separate eye cycles test ordinary blur, a Shell modal, extension disconnect, clean shutdown, and service restart recovery. The observer samples maccel while Minecraft remains focused so switching to the terminal does not hide eye zoom. The test ends only after the original multiplier is independently confirmed, the helper recovery record is absent, the service is stopped, and the GNOME shortcuts are cleared. If any restoration fails, keep eye zoom disabled and retain recovery evidence.
