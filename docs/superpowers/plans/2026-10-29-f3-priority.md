# F3 Priority and Managed Keyd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Ship the tested held-F3 primitive and preserve the five required Minecraft combinations over resize shortcuts.

**Architecture:** Vendor a pinned keyd source tree plus maintained patch, compile/embed its binary, and select it through an owned service override. A shared routing compiler gives keyd and GNOME the same internal resize keys, with a genuine held-F3 priority layer. Runtime activation uses the applied profile and acknowledges GNOME configuration before producing resize signals.

**Tech Stack:** Rust, C/keyd, GNOME Shell JavaScript, systemd.

**Spec:** `docs/superpowers/specs/2026-10-29-f3-shortcut-priority-design.md`

## Global Constraints

- Required: F3+B, F3+G, F3+F, Shift+F3+F, Shift+F3, using native F3 and Tab→F3.
- Preserve standalone F3, modifiers, repeat presses, release order, chat, and resize recovery.
- Preserve distribution binary and foreign files; no development-time system installation or restart.
